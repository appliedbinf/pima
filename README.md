PIMA (Plasmid, Integrations, Mutations, and Antibiotic resistance annotation pipeline) is a high-throughput sequence analysis pipeline.  PIMA is an end-to-end solution encompassing all the steps required to transform raw ONT output into high-quality annotated assemblies.  PIMA supports providing optional Illumina paired end reads for polishing and error correcting assemblies.
  
The PIMA pipeline performs the following actions [Analysis program options in brackets, default first]:
1. Assess FASTQ files and performs basic quality control and downsampling
2. Check for contamination or multiple species present [Optional: kraken2]
3. Assemble reads [Flye, Raven, Spades (if only illumina data is provided), no-assemble]
4. Polish and improve assembly [Optional: Medaka (long reads only); Pilon, Polypolish (illumina reads are provided)]
5. Identify and Annotate plasmids [Optional: minimap2 & pChunks]
6. Annotate plasmid incompatiblity (INC) groups [Optional: blast]
7. Annotate antimicrobial resistance (AMR) genes [Optional: blast with resFinder database]
8. Annotation of user-supplied genomic features (from input FASTA file)
9. Comparison to reference genome provided:
     - including variant calling relative to reference [Varscan]
     - annotation of mutations within AMR-determining regions provided by a bed file [custom Bacillus anthracis file provided]
10. Generate visualizations of the location of detected AMR or user-supplied features [dna_features_viewer]
11. Generate visualization of genome (based on provided reference OR the denovo genome generated) [py_circos]
12. Generate PDF report summarizing all results

# Installation
## Install using prebuilt conda package
A conda package of PiMA is available on our conda channel (appliedbinf)[https://anaconda.org/appliedbinf/dashboard]. Using this package, you can install PiMA into a new conda environment using mamba (preferred) or conda by:
```{bash}
mamba create -n pima -c appliedbinf -c conda-forge -c bioconda pima
mamba activate pima

#view help menu
pima -h

# Download required databases to check for contamination and annotate detected plasmids:
pima --download
```

# Quickstart Guide

## A typical run

Here is an example of a basic run using a fastq file as input.

```
# basic command
pima --output <output_folder> --ont-fastq <my_seqs.fastq.gz> --genome-size <5M> --threads 4 --organism <Bacillus_anthracis>

```

### Expected Outputs
This command will create the following outputs listed in no particular order:
  
1. downsample: folder with a FASTQ with a subset of a high-coverage data set to a given average coverage.
2. info: provides the coverage information of the assembly.
3. ont_assembly: folder with the assembly FASTA file (assembly.fasta) and assembly metrics.
4. quast: folder with the quality metrics and the quast report.
5. medaka: folder with the consensus sequence (consensus.fasta).
5. drawing: folder containing a heatmap of detected amr features and locations of the features on assembled contigs.
6. insertions: folder generated by mummer3 comparing the assembled genome with the provided reference, results are used to extract large INDELs relative to the reference
7. circos: folder containing images of the assembled contigs / their alignments with the reference, and sequence read coverage profiles.
8. mutations: folder containing the results of varscan on detecting SNPs and small INDELs relative to the reference genome.
9. features: provides information on the presence of amr genes and any inserions, if present in the assembled genome.
10. plasmids: folder containing the plasmid annotation results. Contigs <500kb with low similarity to the reference are annotated using the plasmids_and_vectors.fasta reference database.
11. contamination: folder containing the kraken2 classification of the input sequence reads.
14. report: A final report in a pdf format describing the assemblies and other information pertaining to the assembled genome (such as mutations, amr genes identified).

## Input file formats

### Analyzing a single sample
ONT long-read data for a single sample:
* 1 fastq(.gz) file
* 1 sample directory containg a collection of fastq(.gz) files

```
#user has a single fastq file for their sample
pima --ont-fastq <sample1.fastq.gz> -output <output_dir> --threads 2 --organism Bacillus_anthracis

#user is analyzing ont data generated by minknow barcoding kit and wishes to analyze a single sample
pima --ont-fastq <path/to/barcode01> -output <output_dir> --threads 2 --organism Bacillus_anthracis

#example path to barcode01 & contents:
#20250702_Minion_samplename/no_sample_id/20250702_1507_MD-100246_ABC012345_AG01dse/fastq_pass/barcode01
#  FBC06802_pass_barcode01_49e48dbf_3d7f6130_0.fastq.gz
#  FBC06802_pass_barcode01_49e48dbf_3d7f6130_1.fastq.gz
```

Illumina short-read paired end data.
```
pima --illumina-fastq <path/to/R1> <path/to/R2> -output <output_dir> --threads 2 --organism Bacillus_anthracis
```

ONT long-read data and accompanying illumina paired-end data.
```
pima --ont-fastq <path/to/barcode01> --illumina-fastq <path/to/R1> <path/to/R2> -output <output_dir> --threads 2 --organism Bacillus_anthracis --illumina-polisher polypolish
```

### Analyzing multiple samples

The following examples all showcase running multiple samples in serial. See the section [Parallelizing multiple samples with nextflow]() if you have a setup that would allow for multiple samples to be analyzed simultaneous (in parallel).

#### Using a multiplexed minknow output

One common method a running pima is to analyze all the barcodes that were used in a minion barcoding kit. For example, we have 4 isolates that have been prepared for sequencing with barcodes 1 through 4.
PiMA can be given the run folder and will identify all barcodes with >2.5% of the total number of reads generated. This number can be adjusted with the '--barcode-min-fraction' flag. Users can provide the "fastq_pass" folder (recommended) or the entire folder that includes both fastq_pass and fastq_fail reads, in which case, pima will merge these read sets.

All samples are analyzed with the same conditions set (e.g. genome-size = "estimate", the default), reference to use = "Bacillus anthracis"

```
pima --ont-fastq <path/to/fastq_pass> --multiplexed -output <output_dir> --threads 2 --organism Bacillus_anthracis
```

A drawback of this method is you cannot provide separate illumina datasets for each barcode. You can also not pass different flags to the samples, all will be analyzed with the same settings. The next section describes a method that allows more flexiblity in customizing pima settings and allows providing illumina reads per sample.

#### Using a samplesheet

If you wish to run multiple samples from different sequencing runs, or wish to rename the "barcodes" to a sample name you can run pima by providing a sample sheet. You can see an example by running:

```
pima --example-sample-sheet
```
This method also allows you to customize the settings for separate samples.

You still need to provide an --output destination, and within that path PiMA will create a separte results folder for each sample_name in the sample sheet.

```
pima --sample-sheet <path/to/sample_sheet.tsv> --output <path/to/output> --threads <N>
```

Settings specified in the pima command will apply to each sample analzyed, or some options can be specified within the sample sheet itself. The --threads parameter sets the max number a threads that can be used per sample.

#### Parallelizing multiple samples with nextflow

For use with HPC systems, pima has nextflow packaged to allow multiplex analyses to be run in parallel. All the example described in the above section can be run with nextflow by providing the '--nextflow' flag. PiMA has a nextflow.config.template file located in `Pima/nextflow_parallelization` that can be modified for different execution environments. The '--nextflow' parameter typically acts as a flag (i.e. tells pima to run with nextflow) but it  can also accept arguments that will be passed to the wrapped `nextflow -run` command to allow users to also specify ad-hoc, custom nextflow.config files. These must be wrapped in single quotes (see example below).

This has only ever been tested on one HPC system with a SGE scheduler and may be difficult to get running on other executors.

We can provide example job scripts that would also parallelize sample analysis on HPC systems that may be easier to adjust to different environments.


```
#analyzing samples detailed in a sample sheet and parallelizing with nextflow
pima --sample-sheet <path/to/sample_sheet.tsv> --output <path/to/output> --threads <N> --nextflow
```

```
#analyzing multiple barcodes and parallelizing with nextflow
pima --ont-fastq <path/to/fastq_pass> --multiplexed -output <output_dir> --threads 2 --organism Bacillus_anthracis --nextflow
```

```
#providing a custom nextflow.config file
## NOTE: the arguments passed to --nextflow must be wrapped in single quotes
pima --ont-fastq <path/to/fastq_pass> --multiplexed -output <output_dir> --threads 2 --organism Bacillus_anthracis --nextflow '-c <my_hpc_nextflow.config>'
```

## Additional Notes on Optional Arguments

* For error correcting purposes, if illumina reads are used along with ONT reads, this pipeline will map the illumina reads against the ONT assembly. It will then pass the resulting BAM file, and the ONT assembly into Pilon. This will give us a new assembly with errors corrected.
